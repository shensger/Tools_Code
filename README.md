# tools_code

Scripts and tooling.

## ninjaone/

- `Update-NinjaADDocumentation.ps1` – run on a domain controller as a NinjaOne automation; collects AD facts (short name, functional level, Domain Admins, DCs, DNS, DHCP, schema master, RODCs, servers) and writes them into the client's "Active Directory" Documentation document via `Ninja-Property-Docs-Set`.
- `Enable-BitLockerEnforced.ps1` – run as a NinjaOne automation (SYSTEM) on workstations; enables BitLocker on the OS drive or resumes protection on drives that are encrypted with a clear key (Windows auto device encryption). Adds recovery password + TPM protectors, escrows the recovery key to AD / Entra ID / an optional NinjaOne secure field *before* turning protection on, and refuses to enable if escrow fails (exit 3). Saves the key to the NinjaOne Secure field `bitlockerRecoveryKey` by default (create it with Automations = Write); override with script variable `ninjaField`. Other optional variables: `allowNoEscrow`, `skipPolicyKeys`. Exit codes: 0 ok, 1 fail, 2 TPM not ready, 3 escrow failed.

- `Get-EmudhraG3StatusAllOrgs.ps1` – pulls the `emudhraG3Status` / `emudhraStatus` custom fields for every device in every NinjaOne org with the API's bulk custom-field query (a few calls for the whole tenant, not one per device) and writes one CSV row per device: org, device, class, online, last contact, parsed status / exit code / tool / run time, and the raw values. Credentials from `-ClientId`/`-ClientSecret`, `NINJAONE_CLIENT_ID`/`NINJAONE_CLIENT_SECRET`, or the NinjaOne MCP server's env block in the Claude Desktop config (secret never printed). Prints a count per status.

## macos/

- `distrust-emudhra-g3-macos.sh` – macOS remediation for the Oct 2026 eMudhra G3 compromise. Apple blocks the compromised intermediates at the OS level, but `/usr/bin/curl` (and built-in git/python3/openssl) validate against `/etc/ssl/cert.pem` with no revocation check, so they still connect – that's what `test-emudhra-g3.sh` reports as VULNERABLE on Macs (any macOS version). Backs up the bundle, removes `emSign ECC Root CA - G3` by SHA-256 fingerprint, checks a normal HTTPS site still works (restores the backup if not), re-tests `dv-g3b-emudhra.we-have-a-problem.com` with curl's default trust and writes the result to `emudhraG3Status` in the detection script's format. `--include-aaa` (or script variable `includeAaa=true`) also removes `AAA Certificate Services`, closing the Sectigo cross-sign path per the published macOS workaround – off by default because it can break CLI access to legitimate Sectigo sites; the script tests that path and warns if it still connects. `--check` changes nothing; `--rollback` restores the most recent backup. Idempotent – schedule it, since macOS updates can restore `cert.pem`. Exit codes: 0 OK, 1 VULNERABLE/error, 2 INCONCLUSIVE, 3 not root. Does not cover Homebrew, pip/certifi or app-bundled stores.

## activedirectory/

- `Get-ADPasswordExpiry.ps1` – reports each AD user's last password change, password age, expiry date and days until expiry (uses `msDS-UserPasswordExpiryTimeComputed`, so fine-grained password policies are honored). Each user gets a Status of `Expired`, `ExpiringSoon`, `OK`, `NeverExpires` or `MustChange`, ready to pipe into an alerting step. Parameters: `-SearchBase`, `-Server`, `-WarningDays` (default 14), `-IncludeDisabled`, `-OnlyAlertable`, `-CsvPath`. Requires the ActiveDirectory module.

## linux/

- `distrust-emudhra-g3.sh` – blocklists the compromised eMudhra trust path (Oct 2026 intermediate key compromise) on RHEL-family hosts that can't get a fixed `ca-certificates` package (e.g. EOL CentOS Stream 8). Blocklists `emSign ECC Root CA - G3` and `EM DV TLS CA - G3B`, SHA-256 fingerprint-checks both before writing, runs `update-ca-trust extract`, then confirms `curl` rejects `dv-g3b-emudhra.we-have-a-problem.com`. Handles RHEL 8 `blacklist` and RHEL 9 `blocklist` dirs; idempotent. `--check` verifies without changing anything. Exit codes: 0 rejected (good), 1 error, 2 applied but still connecting, 3 `--check` vulnerable. Does not cover certifi, Node or Go bundles.
- `distrust-emudhra-g3-ubuntu.sh` – Ubuntu/Debian equivalent. Finds `emSign ECC Root CA - G3` in `/etc/ca-certificates.conf` by SHA-256 fingerprint, backs up the conf, prefixes the line with `!`, runs `update-ca-certificates --fresh`, then confirms `curl` rejects the test host. Removing the root breaks all G3B/G3C chains, so no intermediate blocklist is needed. Idempotent; no-op if the root is already gone. Exit codes: 0 OK, 1 error, 2 applied but still connecting. Verify afterwards with `cross-platform/test-emudhra-g3.sh`.
- `distrust-emudhra-g3-cloud.sh` – Amazon Linux 2 / 2023 and Azure Linux 3.0 / CBL-Mariner 2.0 version (bash + coreutils only; the AL images have no openssl, the Azure images no awk). Updates `ca-certificates` from the vendor repo first (AL2023 via `--releasever=latest`, since its version-locked repo doesn't carry the fix; AL2 `yum update`; Azure/Mariner `tdnf`), then scans the extracted TLS bundle by SHA-256 fingerprint and, if `emSign ECC Root CA - G3` is still there, blocklists it via p11-kit (`blocklist`, or `blacklist` on AL2) and re-extracts. Tested in the official images: the AL2023 (`…amzn2023.0.4`) and AL2 (`…amzn2.0.3`) packages remove the root; Azure Linux 3.0 doesn't ship it; Mariner 2.0 has no vendor fix and gets blocklisted. `--include-aaa` also distrusts `AAA Certificate Services` (the Sectigo cross-sign path) – needed on Mariner, which trusts it for TLS; Amazon Linux already keeps it out of the TLS bundle. Rolls back its own blocklist files if `aws.amazon.com` / `www.microsoft.com` stops working, reports app-bundled CA files (AWS CLI v2, Azure CLI, certifi, `/opt`) still containing the root without editing them, and writes `emudhraG3Status` when the NinjaOne agent is installed. `--check`, `--no-update`, `--rollback` (removes the blocklist files; doesn't downgrade the package). Script variables `ninjaField`, `includeAaa`, `noUpdate`. Exit codes: 0 OK, 1 VULNERABLE/error, 2 INCONCLUSIVE, 3 not root.

## aix/

- `distrust-emudhra-g3-aix.sh` – AIX remediation for the Oct 2026 eMudhra G3 compromise (ksh, no bash needed; run as root). AIX has no single trust store, so it discovers them: `OPENSSLDIR/cert.pem` and the `certs/` hash dir for every openssl (IBM `openssl.base` in `/var/ssl`, AIX Toolbox in `/opt/freeware`), the CAfile/CApath each curl reports, and the usual Toolbox bundle paths. Removes `emSign ECC Root CA - G3` by SHA-256 fingerprint from every bundle (in place, permissions kept), moves its hash-dir entries aside, and, when Toolbox p11-kit `update-ca-trust` is installed, also blocklists it there so a re-extract keeps it out. Live-tests `dv-g3b-emudhra.we-have-a-problem.com` with every curl and openssl found; on hosts with no egress the verdict falls back to the offline store scan. IBM Java `cacerts` (WebSphere etc.) are reported; `--include-java` deletes the alias with keytool after a backup. Everything is backed up under `/var/adm/emudhra-g3/<timestamp>/` with a manifest; `--rollback` undoes the last run, and a run that breaks `www.ibm.com` (when it worked beforehand) rolls itself back. `--check` changes nothing. Idempotent – run from cron, since Toolbox `ca-certificates` / `openssl.base` updates can restore the root. Exit codes: 0 OK, 1 VULNERABLE/error, 3 not root. Does not cover GSKit `.kdb` stores (IHS, MQ, Db2), certifi or app-bundled CA files. No NinjaOne field (no AIX agent).

## cross-platform/

- `test-emudhra-g3.sh` (macOS / any Linux, POSIX sh) and `Test-EmudhraG3.ps1` (Windows PowerShell 5.1 / 7) – the equivalent of `curl -sS https://dv-g3b-emudhra.we-have-a-problem.com/ ; echo "exit=$?"` on each OS, using the OS trust store. Prints the output, `exit=N` and a verdict: a TLS/cert failure (curl 35/51/58/60/77) is **OK** (compromised eMudhra G3 chain not trusted), exit 0 is **VULNERABLE**, anything else is **INCONCLUSIVE**. Exits with curl's exit code. Under the NinjaOne agent (Windows `Ninja-Property-Set`, macOS/Linux `ninjarmm-cli`) both write `OK|VULNERABLE|INCONCLUSIVE | exit=N | tool | timestamp` to device text field `emudhraG3Status` (script variable `ninjaField` overrides, `none` disables) and exit by verdict instead (0 OK, 1 VULNERABLE, 2 INCONCLUSIVE) so a pass doesn't show as a failed run. Shell version falls back to `wget`; PowerShell calls `curl.exe` explicitly (not the PS 5.1 alias) and falls back to `Invoke-WebRequest`. Optional first argument / `-Url` overrides the test URL.

## autoelevate-mcp/

- MCP server for AutoElevate (CyberFOX) built on the admin portal's internal API. `ae_analyze_request` runs a CMMC Level 2 / NIST 800-171 Rev 2 pre-approval analysis on an elevation request (signature, VirusTotal, CISA KEV + NVD for the exact version, EOL, client software baseline, restricted categories, shells/LOLBins, device posture) and returns a verdict plus a ConnectWise note. `ae_decide_request` approves/denies only with confirmation, a fresh analysis, and a recorded override reason when going against the verdict. `ae_audit_rules` flags risky existing rules. See `autoelevate-mcp/README.md`.
